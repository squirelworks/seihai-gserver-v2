The sixth Seihai release of **GServer-v2** (`gs2emu`), the lab reference server the Seihai Rust servers are checked against. It follows `v4.0.0-seihai.5` (2026-11-20). The headline is the **Graal 3D add-on**: the UDP side that the 3.151 to 5.x clients' Torque 3D mode talks to, now an optional add-on that can be built in or shipped as its own module. Licence: GPL-3.0, as upstream. The original authors are credited in `README.md`.

Every change is listed in `CHANGES-SEIHAI.md`, with the files changed and how each was checked.

## Graal 3D add-on

The 3D side runs only with `graal3d = true` in `config/serveroptions.txt`; with that off the server behaves as upstream. A server built with `-DGRAAL3D=OFF` has no 3D code at all.

- **Its own module (#184).** The add-on reaches the server only through a small interface (`AddonHost`), so it can be built as `seihai-graal3d` (`libseihai-graal3d.so`, `seihai-graal3d.dll`, `libseihai-graal3d.dylib`). A server built with `-DGRAAL3D=OFF` loads it at start when `graal3d = true`, as the Seihai gserver starts its NPC-server. The module has its own version (`addons/graal3d/VERSION`, 0.1.0) and its own `graal3d-v*` releases. The loader refuses a module built for another add-on API, toolchain or gs2lib version table, logs why, and runs on without 3D. The built-in add-on (`GRAAL3D=ON`, the default) is unchanged. See `docs/addons.md`.
- **Per-build 3D capabilities.** One row per 3D client build (3.04 to 5.12, Windows and Mac), mirrored from Seihai's version profile. Terrain and water layouts go only to builds that take them.
- **Checks on everything the 3D side serves.** `.3ds` faces and textures, `.dts` counts and size, `.dif` interior versions, PNG size, replicator shapes and textures, and bare file names only. Files known to crash a real client are refused.
- **Several players in one world**, with the TCP position following the 3D object.
- **Terrain.** Pushed by default (`graal3dpushterrain`), also at TCP login; Phase 2 of the mission start is held until the terrain is in, so the client lights it (T3D-162).
- **Grass and ground cover.** Replicator lines with `box` and `scale=`, grass textures pushed on link and at login.
- **Big worlds (#183).** The player's own object and Camera are ghosted first, so a world of 4,094 or more objects no longer leaves the view black. `graal3dscope` ghosts world objects near each player only (at most 3,584 a client, nearest first; off by default). Terrains up to 256 x 256 chunks stream as a 16 x 16 window round the player. `graal3dsendms` sets the least time between data packets.
- **6.037 may link to 3D**, and junk logins are closed early (#181). 4.20r8 gets no login files; a use-after-free on link close is fixed (#178).
- **Lab tools.** `graal3dmutate` (seeded one-shot mutations, lab only), `rawobject`/`rawevent` world lines, the `sharp3d` comparison route, and `tools/lab/g3dlabworlds.py`.

Ported from seihai-gserver, which also has regions, `portal` doors and interiors, several worlds, in-game staff editing and per-player objects. Those are not in GServer-v2.

## Other fixes

- **Merged upstream `beta4` at `f98c1d5`** (2026-11-24).
- **Script copies keep their own source (#156).** A copied or moved script could point into freed memory: a level NPC whose whole script was `sparringzone` reached the client as 12 bytes of process memory on a world with no NPC-server.
- **GS2 lambdas are numbered from the server's compile count (#179)**, as the official server does, so two scripts no longer give two lambdas the same name.
- **Weapon reload crash (#161)** fixed.

## Known limits of the 3D mode on a real client

- A client holds at most **4,096 ghosts**. Big towns need `graal3dscope`; a town at the 3,584 cap ran at 11 to 12 FPS under software rendering.
- **A world switch into a world with no terrain, water or Sun freezes a 5.12** on a sky-only frame. Give every 3D world at least a Sun.
- No ground cover is drawn while the player stands in the origin cell.
- Windows without a GPU driver has only Microsoft's GDI OpenGL 1.1, which some 3D builds draw badly or crash on (4.20r8 terrain); install a driver or use Mesa.
- `KNOWN-ISSUES.md` has the rest.

## Download

Pick the archive for your system: Linux x86_64 or Windows x86_64, plus macOS Intel and Apple Silicon when they are attached. Unpack it and run `gs2emu --server default` (or `classic`, `modern` or `npcdemo`). On macOS, the first start may need right-click → Open, because the build is not signed. `SHA256SUMS` lists the checksum of every file attached.

The separate 3D module is its own release, `graal3d-v0.1.0`. The **add-on package** (`seihai-gserver-v2-graal3d-addon-*.tar.gz`), for patching the 3D side into upstream GServer-v2 `beta4` or running the prebuilt Linux module, is attached when available; its `README.md` has the install steps.

The full source for this release is attached as the `-source` archive, as the GPL requires.
