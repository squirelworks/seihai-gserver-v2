The third Seihai release of **GServer-v2** (`gs2emu`), the lab reference server the Seihai Rust servers are checked against. It adds everything on the `seihai` branch since `v4.0.0-seihai.2` (2026-11-13): crash and bounds fixes from seihai-gs2lib, GS1 scripts that 5.12 and later clients actually run, 1.x clients that draw other players, 5.24r3/r4 logins, default fonts for 5.x and 6.x, and a Graal 3D game side for protocol 19. Licence: GPL-3.0, as upstream. The original authors are credited in `README.md`.

Every change is listed in `CHANGES-SEIHAI.md` (sections 2026-11-13 to 2026-11-16), with the files changed and the clients each change fixes.

## Upstream

No new upstream `beta4` merge since `v4.0.0-seihai.2`. gs2lib now comes from seihai-gs2lib `df5b9a6`.

## Stability

- **gs2lib crash and bounds fixes** (seihai-gs2lib #22–#26, #30): sockets use the address family the name resolved to, RC/NC version labels stay inside the token table, bytes left after a short or blocked send are drained, cipher generations are clamped, and out-of-range reads in the string, codec and websocket helpers are stopped.
- **A GS1 script that fails at run time no longer crashes the server** (a use-after-free in Release builds).
- **Torque bit stream bounds.** 3D-side bit reads and writes wider than 32 bits, and patches past the end of the buffer, no longer hit undefined behaviour.

## New

- **5.24r3 and 5.24r4 can log in** (`CLVER_5_24`), and 13 more builds from the Graal_analysis token catalogue get version ids instead of `CLVER_UNKNOWN`. iPhone Classic+ 1.13 gets its id too.
- **GS1 for 5.12 and later.** GS1 client scripts and GS1 weapons reach 5.12+ clients as GS2 bytecode, translated only to calls real 5.24r4 and 6.03r7 have. Player flag writes go to the server through `gr.flagset`, and the stock movement weapon no longer sends position flags every tick.
- **Default fonts** in the `default` and `modern` worlds (Liberation Sans, SIL OFL 1.1, saved under the names the clients ask for), so 5.24r4 and 6.03r7 draw text. 6.03r7 uses only fonts already cached at start, so its first visit still draws no chat text.
- **Graal 3D protocol 19** (3.153, 4.04r2) gets a game side, and the Linux 3.151 client may connect. Real 3.151 and 3.153 reach the control object, then crash on their first frame; see `bin/docs/graal3d.md`.
- **Lab switch `legacyprops_drop`** to leave chosen props out for 1.x clients without a rebuild.

## Fixes

- **1.x clients draw other players' bodies** (status bit 4 means "swimming" to 1.x) and get player props in the forms they read on newmain and modern servers.
- **Server warp waits for file transfers.** The 178 warp from a login server is held until the client's file requests go quiet, so 5.24r4 and 6.03r7 keep `pics1.png`.
- **Files for clients before 2.1** no longer gain an extra line feed, and a zero-byte file still sends one body.
- **RC props set** keeps bomb power and the level of an offline account.
- **Tests.** The stale GS1 and ScriptEventQueue tests build, pass and run in CI.

## Known gaps

- Real 3.151 and 3.153 crash on their first 3D frame; Windows 4.04r2 crashes in its own 3D start; 4.20r8 is protocol 24 and not served.
- Several GS1-for-5.12+ changes are covered by unit tests and loopback only.
- macOS archives are built at release time when a macOS runner is free. If they are missing, build from the source archive.

## Lab worlds included

The same four worlds as `v4.0.0-seihai.2` (`default`, `classic`, `npcdemo`, `modern`), all listening on loopback only. See `bin/docs/lab-world.md`; Graal 3D hosting is in `bin/docs/graal3d.md`.

## Download

Pick the archive for your system: Linux x86_64 or Windows x86_64, plus macOS Intel and Apple Silicon when they are attached. Unpack it and run `gs2emu --server default` (or `classic`, `modern` or `npcdemo`). On macOS, the first start may need right-click → Open, because the build is not signed.

The full source for this release is attached as the `-source` archive, as the GPL requires.
