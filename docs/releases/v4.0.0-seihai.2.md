The second Seihai release of **GServer-v2** (`gs2emu`), the lab reference server the Seihai Rust servers are checked against. It adds everything on the `seihai` branch since `v4.0.0-seihai.1` (2026-11-11): upstream `beta4` up to `2de276b`, Seihai's secure login, Graal 3D hosting, working GS2 script caches, fixes to RC and NPC-Control found with archived RCs, and support for the Mac PowerPC clients. Licence: GPL-3.0, as upstream. The original authors are credited in `README.md`.

Every change is listed in `CHANGES-SEIHAI.md` (sections 2026-11-11 to 2026-11-13), with the files changed and the clients each change fixes.

## Upstream

Upstream `beta4` is merged up to `2de276b` (2026-11-11). That brings board changes on the right gmap sublevel, `shoot` for modern clients, reworked property serialization, gmap positions clamped to the map, no client lock-up on a warp to an unknown gmap, and the password hidden in the packet log. gs2lib comes from seihai-gs2lib `084a516`.

## New

- **Secure login (`SEI00001`).** A Seihai client can send its account and password sealed instead of in the clear. It uses X25519/Ed25519 and ChaCha20-Poly1305. Real Graal clients log in as before. See `bin/docs/secure-login.md`.
- **Graal 3D hosting** for the 3.153 to 5.x clients, on `serverport + 1` when `graal3d = true`:
  - the Torque UDP connect;
  - a world from `config/graal3dworld.txt` (objects, Sun, Sky, spawn, an optional camera per client);
  - a ghost per linked player, and 3D-side weapon scripts;
  - player moves through `triggerserver(..., "g3dpos", x, y, z)`.
  A 5.12 lab client reaches login step 6.
- **Ping for game clients.** `PLI_PONG` (162) is accepted. The new `clientping` option sends `PLO_PING` (108) to the builds that answer it: 4.20r8, and 6.01r1 to 6.037.
- **Mac PowerPC clients.** 4.04r2, 4.20r6 and 5.12 for the Mac each have their own version id. They get the server warp (178), their own cipher step rule, and ping on 4.20r6.
- **Lab harness.** `tools/lab/labcheck.py`, with one runbook per open lab item in `docs/lab/runbooks/`.

## Fixes

**Game clients**
- **GS2 script caches now match what the client stores**, so clients stop asking for scripts again on every login:
  - 193 for 4.04r2 to 4.20r8;
  - 197 for 5.07 and later, over the DES-encrypted bytecode;
  - class CRCs taken over bytecode, not source;
  - no 197 or 193 for a weapon with no bytecode.
  Real 6.03r7 and 4.20r8 second logins no longer ask again.
- **Missing files.** A client that asks for a missing file always gets `PLO_FILESENDFAILED` (30). Before, it got no answer and 5.12 drew nothing.
- **GS1 weapon text** for 5.07 and older now carries its line breaks as `§`, so the client no longer reads each line as a packet.
- **Classic servers.** A warp to a gmap that a classic-generation server won't load no longer crashes the server, which any 1.x player could trigger. The client gets `PLO_WARPFAILED` instead.
- **Unclosed comments.** A script with an unclosed `/*` comment no longer grows memory until the server dies.
- **Account names.** Names with commas, path parts or control characters are refused, and guests get a positive `pc:` number.
- **2.31 hurt.** A 2.31 hurt sends the hearts once. The account file keeps `PLATFORM win` for 2.x Windows clients.

**Built-in NPC-server**
- `visible`, `#g` and `#G` in level events now work.
- A bare `shootball;` now works.
- A serverside `hurt` now reaches 1.x to 2.31 clients.
- `localhost = true` no longer dials the listserver. The new `localhostlist` option still registers with a lab listserver.

**RC and NPC-Control**
- RC text boxes are quoted the way the RC reads them. Before, server options and folder config came back one word per line and grew on each save.
- Uploads are stored at their real size.
- A folder delete no longer disconnects the RC.
- No broadcasts reach a socket before its login is read.
- Weapon list updates reach every NC.
- An RC reset keeps the account's community name.
- An NPC delete sends 159 once.

**Builds**
- libsodium can come from the system (`secure-login` vcpkg feature).
- The Catch tests link on macOS.

## Tested with real clients (lab, 2026-11-13)

Loopback only, with Wine for the Windows clients. The notes are `docs/lab/2026-11-13-real-client-matrix.md` and `docs/lab/2026-11-13-five-clients-one-level.md`.

- **Walk, warp, chat and log out and back in** pass on 1.39, 1.41r1, 2.05r2, 2.17.1, 2.22 and 2.31. The gmap edge passes on 2.22 and 2.31.
- **The `modern` world.** 4.20r8, 5.12 and 6.03r7 log in, get the `.gpake` key first and draw the packaged image.
- **A real 2.22 RC.** Account edits keep the admin fields, folder rights save, and banning an online player does not hang the server.
- **One level, five clients.** 1.39, 2.22, 2.31, 5.12 and 6.03r7 stayed in one level for over 70 s. Every client got every other client's movement, and chat from the 1.x and 2.x clients reached all the others.

## Known gaps

- 5.24r4 (`G3D15010`) is not in the version table yet.
- 1.39 does not draw other players in a shared level, and the classic world has no GIF copies of `sword1.png` and `shield1.png`.
- 3.153 was not part of this lab run.
- macOS archives are built only when a macOS runner is free. If they are missing, build from the source archive.

## Lab worlds included

These are the same as `v4.0.0-seihai.1`:

| World | Clients | Port |
|---|---|---|
| `default` | 2.00 to 3.153 | 14802 |
| `classic` | 1.33 to 1.41r1 | 14803 |
| `npcdemo` | the built-in NPC-server | 14804 |
| `modern` | 4.04r2 to 6.037, and their resource packages | 14805 |

All four listen on `127.0.0.1` only. See `bin/docs/lab-world.md`; Graal 3D hosting is in `bin/docs/graal3d.md`.

## Download

Pick the archive for your system: Linux x86_64 or Windows x86_64, plus macOS Intel and Apple Silicon when they are attached. Unpack it and run `gs2emu --server default` (or `classic`, `modern` or `npcdemo`). On macOS, the first start may need right-click → Open, because the build is not signed.

The full source for this release is attached as the `-source` archive, as the GPL requires.
