## Leads, ranked

1. **197 for a weapon with no bytecode.** `-gr_movement` is GS1, so it has no bytecode. The fork still sends 197 `weapon,-gr_movement,1,<key>,<crc>` with CRC = CRC32 of nothing = 0. Per Graal_analysis `formats/windows-603-weapon-cache.md`, CRC 0 skips the comparison and leaves cache success false, so 6.03 asks for the script (158); `Weapon::sendByteCodeToPlayer` then sends nothing because the bytecode is empty. The weapon never loads. The Rust server sends no weapons at all. Test: same world with no GS1 weapons for 6.x (or the fork not sending 33/197 for a weapon without bytecode to >5.07 clients).
2. **168 ONLINEMODE + 194 RESETCLIENT right after the signature.** 168 "resets the local player; sent by the login server" (manual 2.5.4). The Rust server sends neither.
3. Extra start-up messages the Rust server omits: 179, 41, 82, 47, 34 x2, 0, 4, 174.
4. The Rust server sends 182 LISTPROCESSES; the fork does not (anti-cheat scan, probably unrelated).
